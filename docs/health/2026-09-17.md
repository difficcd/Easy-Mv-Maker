# Health check — 2026-09-17

A dated look at the software and the repository, with each weakness filed as an issue so it is
tracked, not just noted. Redo this when the shape of the code changes, and add a new file rather
than editing this one, so the trend stays readable.

Numbers: 363 commits, 338 tracked files, 1,170 unit tests, `src/App.jsx` 2,421 lines (from 3,140
in September), 30 hooks, 46 modules under `src/core`.

## What is in good shape

- **Structure.** `core/`, `engine/` and `export/` touch neither React nor a canvas, and that is
  enforced by the tests being framework-free. App.jsx has lost a quarter of its length to hooks
  and a tool dispatch table. `HELPERS.md` (every shared export, checked) and `ARCHITECTURE.md`
  are kept honest by `npm run check`.
- **The gate.** Typecheck, the unit tests, six static guards (hook baseline, helper index,
  unreachable names, unused imports, stroke writes, i18n) and the build, on every push and PR;
  a smoke test that actually draws and undoes.
- **One principle carried through.** Every effect is a pure function of the time, so the export
  repaints exactly what playback showed. Performance work is measured and written down
  (`docs/perf/`).
- **Process.** Branch → PR → CI → rebase-merge, every time. Issues carry the requirements; the
  wiki and the README exist in two languages.

organisation, and the code organisation is better than it was a month ago. The single largest

2026-09-22 (done): `App.tsx`, `main.tsx`, `db.ts`, `i18n.ts`. Nothing under `src/` is JavaScript,

Weakness 5 is closed. App under strict turned up `resizeAudio` typed as if both edges carried
every field (the protocol is one edge, one set of fields) and a group drag typed as moving cuts
when it moves placements. #268 can close.

2026-09-23: the document types are sealed. `document.d.ts` said in its own header that it was
"deliberately not sealed with an index signature", while all four interfaces carried
`[extra: string]: any` - so a misspelt field on a cut or a layer was still never an error, which
is the one thing the file exists to prevent. Every field is written down now (35 of them, all
real), the index signatures are gone, and `CutText` extends the renderer's `TextObject` rather
than describing the same text twice.

Two id types came out of it: a cut, layer, stroke or text is identified by a **number** from
`nextId()`, a part or an import batch by a **string**. Both were `Id = number | string` and used
interchangeably, so a part id could be assigned to a cut id. `DocId` and `PartId` say which.

What sealing found: `TextObject.outline` was typed `number` ("stroke width in px") while the
renderer reads it as a flag - its own comment says the width follows the font size - and the
editor writes a checkbox into it; `TextEdit.align` was `string` against the renderer's
three-value union; `openTextEditorAt` and `floodFillAt` took a cut and then reached past it for
whichever cut was current, a shadowing that let the two disagree; and deleting the last cut
stores `null` in `currentCutId`, which the types now admit rather than claiming a number is
always there. The explicit-`any` count moved only 289 → 274, which is not the measure: what
changed is that every field access on a document object is now checked.
