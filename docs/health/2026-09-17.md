# Health check — 2026-09-17

A dated look at the software and the repository, with each weakness filed as an issue so it is
tracked, not just noted. Redo this when the shape of the code changes, and add a new file rather
than editing this one, so the trend stays readable.

Numbers: 363 commits, 338 tracked files, 1,170 unit tests, `src/App.jsx` 2,421 lines (from 3,140
in September), 30 hooks, 46 modules under `src/core`.

## What is in good shape

- **Structure.** `core/`, `engine/` and `export/` touch neither React nor a canvas, and that is
  enforced by the tests being framework-free. App.jsx has lost a quarter of its length to hooks
  and a tool dispatch table. `HELPERS.md` (every shared export, checked) and `ARCHITECTURE.md`
  are kept honest by `npm run check`.
- **The gate.** Typecheck, the unit tests, six static guards (hook baseline, helper index,
  unreachable names, unused imports, stroke writes, i18n) and the build, on every push and PR;
  a smoke test that actually draws and undoes.
- **One principle carried through.** Every effect is a pure function of the time, so the export
  repaints exactly what playback showed. Performance work is measured and written down
  (`docs/perf/`).
- **Process.** Branch → PR → CI → rebase-merge, every time. Issues carry the requirements; the
  wiki and the README exist in two languages.

## Verdict

For a one-person project this is in the upper range: the process is stronger than the code
organisation, and the code organisation is better than it was a month ago. The single largest
debt is #290, and it is mechanical to pay.
